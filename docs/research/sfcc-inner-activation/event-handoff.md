## Executable frontier probe

- `private_arc_a.rs` registers a test/serde-only diagnostic module.
- `activation_frontier_c.rs` locates the unique single-composite frontier from the
  existing source-family paired-face inventory, then binds the actual current leaf
  and its actual unconsumed FaceRecords. It refuses ambiguous selection, mismatched
  slots/records, invalid point bindings, more than 24 faces or 4,096 needed points.
- `stage4_component_b.rs` invokes that diagnostic before the original private
  construction, retaining its separate result in `activationFrontierC`.

The diagnostic stages only the selected cell's required records and point payloads.
Original positions, normals and provenance keys are copied with an explicit
original-to-local ID map; protected edges whose endpoints are both present and
all their curve memberships are retained. Record segment/pin incidence is copied
without equivalence, clipping or angle changes. The original scene features are
borrowed unchanged. The probe refuses a selected cell with primary20/39 pins so it
does not silently omit that independent primary quotient.

It calls the actual `mesh_cells_subset` for the frontier leaf, under a separate
bounded Transport ledger and the existing 2,048-attempt GeneratedQueries scope.
The source-bound Transport's setup queries and generated reservation are reported
separately from the original constructor's ledger. Every actual generated query
is recorded. No refund or cap change exists. The probe does **not** perform the
constructor's later post-generated domain/transport validation or publish any
returned triangles.

A restoring diagnostic scope preserves the enclosing constructor report on return
or unwind. `NumericalGuard` restores the enclosing failure counters. The ordinary
constructor then runs normally. Live FaceRecords and PointTable are borrowed
immutably throughout; before/after digests are recorded. Local records, local
points and any fallback result are discarded. The result has a 512-KiB serialized
cap and an explicit refusal when unavailable; it is not part of the source-clone
storage ledger or a claim about process RSS.

The precise input boundary is intentionally narrower than complete PointTable

geometry. It cannot be used as an exact split of the existing checked charts while
silently preserving their certificate/provenance semantics. A general feature-set
split would require new source metadata, corner wiring, index/fingerprint/storage
updates and fresh face bindings.

## Native tail must be classified, not merely relabelled

After activation, at E=0 and L<r_inner,

`I = r_inner - sqrt(r_inner^2 + (r_inner-L)^2) < 0`.

If the common chamfer equation Q remains zero, the native E=0 line can lie inside
a smooth Q patch while the physical I=0/Q=0 crease continues elsewhere. To remove
that native tail as a geometric crease, require source proof of strict I>C,
G<0, inactive other ancestors, regular Q and smoothness on both sides of E=0.
A's ghost-family certificate is intended to supply these restrictions; merely
sampling E!=I or seeing the full field near zero is insufficient.

This packet implements no tail pruning, interval rewrite, virtual event, port
merge or publication. The executable probe provides the actual unresolved frontier
inputs while A/B establish the required certificates. Any later transaction must
preserve the repeated-walk guard, query limits, both precision checks, full face
consumers and rollback, then rerun the full affected component.

No component acceptance, native/WASM/GPU equivalence, full-model validity or visual
QA is claimed here. Root execution status and receipts take precedence over this
static author handoff.
