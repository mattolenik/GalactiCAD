## Source and numerical claims stay separate

The proposed certificate borrows one immutable feature registry. It validates the
actual native/inner-field source occurrences, the common generated carrier and
both embedded traced descriptors. The two original ranges are local prefixes
starting at their shared source corner; the different remote ends of curves 46
and 66 are retained and do not become equivalent.

The canonical physical curve uses radius rho, fixed untwisted native coordinate v,
selected signed u=sqrt(rho^2-v^2), and the actual twist at the groove-offset height.
Its interval is rho_min <= rho <= cylinder radius R. Hence C<=0, including equality
at the source junction. The exact source relation E=0 and G=-r then gives a zero
of the original source throughout this interval, once finite profile/closest groove
edge/cap/ancestor conditions hold. Height is affine and strictly increasing in rho,
so this ideal curve is ordered and injective.

The generated common carrier uses its actual represented weight and offset. Its
radius offset/weight is interval-enclosed separately from physical r. The current
reviewed implementation proves closest-edge/cap/ancestor conditions over the whole
hull of these two radii, and bounds physical/generated image separation uniformly
from the affine height shift and rotation Lipschitz bound. It never assumes the
two generated/physical coefficients are exactly equal.

The initial implementation additionally asks for finite native-profile and inactive
inner-round conditions over BOTH full original projection tubes. These would prove
E==inner throughout every original numerical query container, independently of
which branch the common H=max(E,C) uses. The canonical curve's physical exposure
uses rho<=R separately; C<0 is not incorrectly demanded throughout the padded tubes.

Actual numerical events remain fallible. Each accepted event checks the unchanged
own-query result, original projection tube, and direct association to both physical
and generated source images. Height proposes a canonical radius; the actual 3D
association grants authority. Ordered event sequences require strictly ordered raw
parameters on both charts and decreasing canonical radius on both. This is not a
proof of continuity or totality of the old Newton evaluator for every raw parameter.

## APIs and accounting

`exposure_a::alias_a::bind(root, features, source, charts, ranges, rho_min, epsilon)`
performs no actual curve query. Certificate fields are private; getters expose
source roles, chart IDs/ranges, radial range and allowance. Pure `check_point` proves
only container/source association, not that its argument was produced by a query.
`image`, `generated_image` and the two radius-from-height functions expose bounded
source images.

`query_main`, `retained_main` and `map_main` require the original registry instance
and charge `Transport::reserve_external` before actual evaluation, with explicit
external-attempt observation. The existing20/39 Transport is a ledger here, not
46/66 source authority.

`query_generated`, `retained_generated` and `map_generated` require an active
GeneratedQueries scope. Their actual `point_at_checked` calls are counted by its
existing2,048 reservation/log; they do not reserve again. Main-mode calls reject
inside that scope. `transport_generated` checks the SAME stored mesh point directly
against both actual own-query results and both source/container restrictions, so
no tolerance is chained through an intermediate point.

Mapping reuses the existing guarded height proposal for its first two iterations,
then bisection. It invokes at most64 actual queries in a request and at most64
iterations, uses the unchanged16,384 total ledger, and refuses ambiguous windows,
failed actual queries, stagnation and source/ordering discrepancies. There is no
cache or refund. Consumers must additionally restrict mapped parameters to their
actual local target span and retain exact endpoint parameters when required by a
typed face contract.
